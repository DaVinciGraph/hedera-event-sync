## Automatic failure recovery

Version 2.1.0 adds optional automatic retries for queries paused after reaching their consecutive-failure limit. Reading and processing recover independently through the existing resume paths, preserving queued records, processing order, and tracking checkpoints.

Recovery is disabled by default. Enable it when creating the synchronization engine:

```ts
const sync = await HederaEventSync.create({
  restClient,
  querySource,
  failureRecovery: { enabled: true, delaySeconds: 3600 },
});
```

When enabled, the default cooldown is one hour. Each retry resets the stage's failure budget; continued failures trigger another cooldown.

### Lifecycle controls

- Manual pauses, global holds, maintenance, and lifecycle operations take precedence over automatic retries.
- Failure-paused statuses expose `failureRecovery.retryAt` in epoch milliseconds for monitoring and dashboards.
- `holdFailureRecovery()` provides a composable application hold around management work such as database edits before a catalog reload. Call its release function in `finally`.
- Restart and reload preserve cooldowns for retained query IDs. Removing a query retires its schedule, and shutdown stops admitting retries.
- Explicit manual or hook pauses cancel automatic recovery. `{ preserveExistingPause: true }` retains the existing pause ownership and deadline.

### Compatibility

This release introduces no breaking API changes from 2.0.0. Automatic recovery requires explicit enablement. Cooldowns are in-memory state; a fresh process follows its query source and durable checkpoints.
